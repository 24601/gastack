gstack-gastown bridge

Design doc in.
Merged code out.

Event-sourced pipeline connecting gstack design tools to gastown agent execution. Crash-recoverable. Idempotent. Human gates at the right moments.

PLAN — extract tasks from design doc (regex + Haiku LLM)
  ↓
EXECUTE — gt convoy create + gt sling per task → polecats work
  ↓
REVIEW — claude -p /review + claude -p /cso in parallel (Promise.all)
  ↓
  quality.ts → PASS / WARN / BLOCKED
  ↓
REFINE — human approves / rejects / retries (scoped signals)
  ↓
DEPLOY — gt convoy land → refinery merge queue
  ↓
DONE
Six stages. One event log. Kill the process mid-run, restart, it resumes.

The manual handoff tax

Without the bridge

  • Read design doc
  • Manually create work items
  • Manually dispatch to agents
  • Wait for completion
  • Manually run code review
  • Manually run security audit
  • Interpret findings
  • Decide: approve, reject, retry
  • Manually trigger merge

Every step loses context. Every step invites shortcuts.

With the bridge

  • Point at design doc + rig
  • Tasks extracted automatically
  • Convoy created, agents dispatched
  • Event stream tailed in real time
  • Review + CSO run in parallel
  • Quality policy applied
  • Blocks when human judgment needed
  • You decide once, at the right moment
  • Merge lands through refinery

One command. One approval (if needed). Done.

How it works

The interesting engineering problems in building a reliable pipeline between two CLIs.

Event log is the state Zero mutable fields on the Orchestrator. Everything derived from append-only JSONL. Crash → replay log → reconstruct stage, tasks, pending approvals.
Idempotency tokens SHA-256 of (adapter, command, args). Written to log before result processing. Prevents duplicate convoys and reviews on restart.
Scoped approval signals Decisions carry {runId, stage, reviewCycle}. Stale approvals from previous review cycles are ignored. No leaked permissions.
Fail closed on parsing gt --json returns non-JSON → BLOCKED. Never falls back to text scraping. All CLI calls via Bun.spawn with array args. No shell interpolation.
Parallel review execution /review and /cso run simultaneously via Promise.all through the gstack adapter. Halves review time.
Adaptive output 3×3 grid: detail (minimal/standard/detailed) × style (terse/balanced/expressive). Reads filesystem signals. Progresses from verbose to minimal over time.

Quick start

Requires gstack and gastown installed independently. Both CLIs on PATH.

# Install the bridge CLI (requires Bun v1.0+)
$ bun install && bun run build
# Start a pipeline from a design doc
$ bridge start --design-doc ~/.gstack/projects/my-design.md --rig myproject
# Watch events in real time
$ bridge watch <run-id>
# Check pipeline status
$ bridge status <run-id>
# Approve a blocked finding (scoped to stage + review cycle)
$ bridge approve <run-id> --stage REVIEW --cycle 1 --reason "accepted risk"
